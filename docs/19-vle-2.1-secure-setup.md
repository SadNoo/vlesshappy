# 19. `sadno/vle:2.1` 镜像内置安全初始化

## 目标

2.1 保留 2.0 的 VLESS REALITY 数据面、V2 兼容数据库模式、`sort=15`、订阅和计费合同，只简化节点首次部署：

- 不手写 JSON；
- 不在宿主机手工创建 secret 文件；
- 不手工处理容器 UID 65532 的目录权限；
- 数据库密码不进入命令行、环境变量、日志或 `docker inspect`；
- REALITY 私钥只生成在 Docker 命名卷中；
- 面板公开参数与本地密钥不一致时不完成初始化；
- 不修改数据库 schema，不自动写入或创建面板节点。

## 首次初始化

镜像仅发布 `linux/amd64`。创建命名卷并运行交互向导：

```bash
docker volume create vle-node-data
docker run --rm -it \
  --read-only \
  -v vle-node-data:/data \
  sadno/vle:2.1 setup
```

数据库位于 Docker 宿主机且配置地址使用 `host.docker.internal:3306` 时，追加：

```text
--add-host host.docker.internal:host-gateway
```

向导收集：

1. 节点公开地址和 TCP 端口；
2. 已由管理员选择的 REALITY SNI 和 target；
3. MySQL 地址、库名、用户名和隐藏输入两次的密码；
4. 数据库 TLS 模式；`verify_ca` 时同时读取证书 server name 和粘贴的 CA PEM；
5. 自动生成的 REALITY 公钥和 short ID；
6. 管理员把公开材料保存进启用的 `sort=15` 节点后输入其 `ss_node.id`。

`setup` 不生成 SNI、不申请证书、不部署 Caddy/Nginx，也不自动选择第三方 target。SNI/target 的拓扑属于单独的上线决策。

## 完成条件

向导在命名卷的 `/data/.setup` 暂存目录中完成：

- secret owner/mode 检查；
- 配置严格解析；
- 数据库连接；
- `sort=15`、`type=1`、节点带宽和公开参数检查；
- 用户授权快照读取；
- 本地 REALITY 私钥与面板公钥配对；
- 面板公开地址、端口、SNI、target、公钥和 short ID 与本轮向导输出逐项相等；
- Xray 入站构建。

任一步失败都会删除本轮暂存目录，不生成 `/data/runtime`。全部通过后，暂存目录以单次 rename 原子启用为 `/data/runtime`；已经存在的 runtime 永不被 `setup` 覆盖。

数据库暂时不可达或面板字段复制错误时，向导保留本轮临时密钥并显示具体错误；管理员修正后直接选择 `retry`，不需要重新生成公钥。选择 `cancel` 或退出向导才会清理本轮暂存目录。

## 命名卷内容

初始化完成后的卷只包含：

```text
/data/runtime/
├── config.json
├── secrets/
│   ├── vlesshappy_database_password
│   ├── vlesshappy_reality_private_key
│   └── mysql_ca.pem                 # 仅 verify_ca 模式
└── state/
```

权限：

- `/data`、`runtime`、`secrets`、`state`：`0700`；
- `config.json` 和 secret 文件：`0600`；
- owner：运行 UID/GID `65532:65532`。

`config.json` 只保存非秘密运行参数和 secret 绝对路径；数据库密码、REALITY 私钥和 CA 不烧入镜像。命名卷丢失后不能恢复原 REALITY 私钥，必须备份卷或重新生成密钥并同步面板公钥。

## 正式运行

向导根据实际公开端口、容器名、卷名和数据库地址输出完整命令。公网端口为 `2053` 的典型结果：

```bash
docker run -d \
  --name vle-node \
  --restart unless-stopped \
  --stop-timeout 120 \
  --read-only \
  --cap-drop ALL \
  --security-opt no-new-privileges \
  -p 2053:8443/tcp \
  -v vle-node-data:/data \
  sadno/vle:2.1
```

镜像默认用户已经是 `65532:65532`。`2053` 是客户端公开端口，容器内固定为 `8443`；面板公开端口必须与 `-p` 左侧一致。XUDP 在同一 TCP/REALITY 会话中承载，不发布 UDP 端口。

## 兼容与恢复

- `run -config <absolute-path>` 和 `validate -config <absolute-path>` 继续支持 2.0 的 bind mount 手工部署；
- `keygen` 保持原行为；
- 2.1 默认配置路径改为 `/data/runtime/config.json`；
- `setup` 检测到 runtime 已存在时直接拒绝，不提供覆盖或重置开关；
- 删除容器不删除命名卷；删除命名卷会永久丢失本地秘密；
- 需要修改公开参数或轮换密钥时，先备份并按单独运维流程创建新卷，不在原卷上就地强制覆盖。
