# 21. `sadno/vle:2.2` 受管 Caddy 与非443端口

## 冻结合同

- 协议仍为 VLESS + RAW/TCP + REALITY + Vision + XUDP；
- 面板公开串仍保存 SNI、公钥和 short ID，不保存私钥；
- 2.2受管格式省略 `target=`，后端固定 `127.0.0.1:9443`；
- 容器内 VLESS监听8443，Caddy HTTP-01监听8080，Caddy HTTPS只监听 `127.0.0.1:9443`；
- 公网 VLESS端口由管理员选择，但80保留给 ACME；
- 不自动创建 DNS记录，不读取 DNS服务商 token，不修改防火墙；
- 不新增或修改数据库表。

示例：

```text
node.example.com;2053;0;tcp;reality;sni=decoy.example.net|pbk=<PUBLIC_KEY>|sid=<SHORT_ID>
```

`minver`非空时才追加。完整字符串仍不得超过 `ss_node.server` 的255字节限制。

## 初始化和秘密

`setup` 隐藏读取数据库密码，生成每节点独立的 X25519 REALITY密钥和8字节 short ID，只输出公开字符串。成功目录增加：

```text
/data/runtime/caddy/
├── Caddyfile
├── config/
├── data/          # ACME账户、证书和证书私钥
└── site/index.html
```

整个目录及子目录为0700；生成配置和默认站点为0600。REALITY私钥继续位于 `/data/runtime/secrets/`。镜像不包含任何运行时密钥、证书、域名或数据库凭据。

首次正式启动依次完成数据库和节点校验、Caddy启动、受信任TLS 1.3环回握手，再启动 Xray监听。五分钟内无法取得匹配 SNI的证书则启动失败；已有缓存证书时不依赖每次启动重新签发。Caddy异常退出会触发数据面排空并停止容器。

## DNS和端口

管理员必须提前创建 SNI域名的 A/AAAA记录。HTTP-01规范仍从公网80访问，所以运行命令必须把宿主80映射到容器8080，或由中转把 TCP/80透传到该入口。公网 VLESS端口不要求443，例如：

```text
宿主80   -> 容器8080 Caddy HTTP-01
宿主2053 -> 容器8443 VLESS REALITY
容器loopback 9443 -> Caddy HTTPS
```

外部443不是运行必需项。浏览器访问 `https://<SNI>:<VLESS公网端口>` 时，非 REALITY连接会由 Xray转到本地 Caddy。

## 固定中转

中转只改变公开地址和端口：

```text
relay.example.com;3053;0;tcp;reality;sni=decoy.example.net|pbk=<PUBLIC_KEY>|sid=<SHORT_ID>
```

中转必须逐字节透传 TCP，禁止 TLS终止、HTTP反代和 PROXY protocol。XUDP仍封装在同一条 TCP/REALITY连接中，不需要单独转发 UDP。源站看到的来源IP是中转IP；用户认证和计费仍由源站完成。

如果 SNI解析到中转IP，中转必须至少把 TCP/80转发到源站 Caddy HTTP入口；若要求标准 `https://<SNI>` 也可直接打开，还需把 TCP/443转发到 Caddy HTTPS入口。第一版不自动消费 SSPanel的动态 `relay_rules`，只支持节点字符串中的固定中转入口。

## 2.1兼容边界

带 `target=` 的旧节点继续由解析器接受，但它被视为手工外部 target 模式，运行配置不能设置 `caddy_dir`。受管 Caddy配置与旧外部 target混用会明确拒绝，避免面板 target悄悄绕过本地安全边界。
