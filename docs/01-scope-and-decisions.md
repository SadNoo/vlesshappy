# 01. 范围与设计决策

## 1. 目标

建设一个与现有 SSPanel-Uim-Anankke 用户、节点、计费和订阅体系兼容的 VLESS REALITY 后端，达到既有 V2 后端与 SS2022 后端的生产标准：

- 真实用户级认证和统计；
- 多用户单端口；
- TCP 与端到端 UDP 代理；
- 用户额度、到期、等级、分组、节点带宽、封禁策略实时生效；
- 活跃来源 IP、设备数限制、在线数和节点状态上报；
- 原始流量统计、倍率计费、可靠重放和幂等入账；
- 数据库故障期间的有界降级与超时 fail-closed；
- 容器化 Linux/amd64 首发和长时间稳定性验证；
- `?vless=1` 独立订阅及现有客户端聚合订阅接入。

## 2. 首版范围

### 2.1 包含

- 节点类型：`sort=15`。
- 入站：VLESS。
- 传输：RAW/TCP。
- 传输安全：REALITY。
- 流控：`xtls-rprx-vision`。
- UDP：XUDP，必须通过 DNS、普通 UDP、IPv4/IPv6 端到端测试。
- 用户身份：父项目 UUIDv3 DNS 映射 `id|passwd`。
- 平台：Linux/amd64；代码不得阻止后续 Linux/arm64。
- 数据库：MySQL，与父项目现有 schema 及本目录新增迁移兼容。
- 订阅：标准 VLESS URI、Mihomo 配置、第一方客户端聚合配置。

### 2.2 不包含

- 原生 UDP 入站监听；VLESS/XUDP 不得宣传为原生 UDP 传输。
- WebSocket、HTTPUpgrade、mKCP、XHTTP、gRPC、普通 TLS。
- VLESS Encryption、ML-KEM VLESS 用户加密实验功能。
- 多节点单进程；首版一个进程服务一个 `node_id`。
- 自动申请域名、证书、REALITY target 或自动修改防火墙。
- 直接修改父项目目录；集成材料只在 `panel-overlay/` 中生成。
- 自研 REALITY、TLS、XTLS、VLESS 或密码学实现。

## 3. 关键术语

- **原始流量**：客户端和目标之间被代理的用户有效上下行字节，不乘节点倍率。
- **计费流量**：原始流量乘 `ss_node.traffic_rate` 后写入 `user.u/user.d` 的值。
- **XUDP**：在 Xray/VLESS 会话内承载 UDP 数据报的机制，不等于节点监听原生 UDP socket。
- **授权快照**：最近一次从数据库完整、正确编译出的节点用户与策略集合。
- **流量 outbox**：数据库入账前先原子落盘的不可变流量批次。
- **fail-closed**：无法确认授权或无法保证计费时，拒绝新代理会话，而不是继续开放服务。
- **会话撤销**：不仅删除新连接凭据，还主动终止该用户已经建立的 TCP、Mux 和 XUDP 会话。

## 4. 实现模型选择

### 4.1 采用

采用“固定上游版本的 Xray-core + 最小 SSPanel 适配与连接钩子”的单进程模型：

- 上游负责 VLESS、REALITY、Vision、XUDP 和数据转发。
- 自有代码负责 MySQL、用户快照、策略编译、会话索引、计费、outbox、节点状态和生命周期。
- 对 Xray 的改动限制为清晰、可测试、可重放的 hook patch；协议与密码学包保持上游原样。

### 4.2 不采用的方案

| 方案 | 不采用原因 |
|---|---|
| 旧 v2lite 上直接增加 REALITY | 核心版本过旧，发行构建排除 VLESS，不具备现代 REALITY。 |
| 完全原版 Xray + 定时脚本 | 可以动态加删用户和读取流量，但不能可靠完成用户来源 IP、既有会话撤销、最终解析 IP 策略和 exactly-once 计费。 |
| 重写 VLESS/REALITY | 安全风险和维护成本不可接受，也没有业务价值。 |
| 通过旧 `/mod_mu` 完成全部计费 | 旧接口没有批次幂等和事务性 exactly-once 语义，数据库失败时容易部分入账。 |

## 5. 冻结运行默认值

默认值必须可通过严格配置覆盖，但不得接受未知配置项。

| 项目 | 默认值 |
|---|---:|
| 授权刷新间隔 | 60 秒 |
| 节点状态/活跃 IP 上报 | 60 秒 |
| 流量批次间隔 | 60 秒 |
| 首次数据库连接/查询超时 | 15 秒 |
| 数据库重试 | 1 秒起，指数退避到 60 秒并加抖动 |
| 授权快照最大陈旧时间 | 3600 秒 |
| TCP 每用户连接上限 | 800 |
| TCP 全局连接上限 | 3000 |
| 并发握手上限 | 1024 |
| XUDP 每用户会话上限 | 128 |
| XUDP 全局会话上限 | 2048 |
| XUDP 空闲超时 | 60 秒 |
| 优雅停止上限 | 120 秒 |
| outbox 最大未入账字节 | 默认 1 GiB，达到 80% 告警，达到上限停止接收新会话 |

这些数值是安全初值，不是性能承诺；最终可在压测后调整，但调整必须记录基准测试证据。

## 6. 已冻结但仍待执行验收的事项

- 已固定 Go 1.26、Xray-core `v1.260327.0` 和 module 校验；最小补丁见 `core/`。
- REALITY 默认最低客户端版本与实际客户端矩阵。
- Linux/arm64 是否进入首发或后续版本。
- target 同 ASN 检查采用部署时人工门禁还是可选自动检查。
- 父项目 overlay 的最终应用时机。

以上事项可以在实施阶段填入具体值，但不得降低本文件定义的授权、计费和安全标准。

## 7. 简化原则

- 每个阶段只实现该阶段验收所需的功能，不提前加入其他协议、传输或通用插件系统。
- 先选择标准库和上游 Xray 能力，再考虑增加依赖或自有抽象。
- 一个概念只有一个权威实现；避免多套配置模型、重复 DTO 和兼容分支。
- 能用一个清晰函数解决的问题，不建立框架、注册表或事件总线。
- 性能优化以基准测试为前提，不用推测增加缓存、并发层或对象池。
- 代码行数不是唯一指标，但复杂设计必须证明简单方案无法满足正确性、安全或可靠性要求。
