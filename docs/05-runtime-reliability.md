# 05. 运行时与可靠性

## 1. 首次启动

启动顺序必须固定：

1. 解析并严格校验配置。
2. 检查 secret 文件类型、所有者和权限。
3. 锁定状态目录，防止同一节点两个实例共用 outbox。
4. 扫描并验证所有历史 outbox；任一文件损坏时拒绝启动，不得自动删除。
5. 连接数据库并校验 schema 版本、`node_id`、`sort=15` 和节点配置。
6. 读取、编译第一份完整授权快照。
7. 构造 Xray 入站并完成自检。
8. 开始监听。

数据库不可用、节点不存在、节点类型错误、REALITY 密钥不匹配或第一份快照无效时，都不得先监听再等待修复。

## 2. 授权刷新

- 默认每 60 秒读取一次完整授权输入。
- 以不可变快照编译，验证成功后一次原子指针交换。
- 对比旧快照生成新增、删除、凭据变化、策略变化和节点全局状态变化。
- Xray 用户变更失败时，新快照不得发布；已成功的部分操作必须回滚或重建到旧快照。
- 用户被删除、禁用、到期、超额、UUID 变化或策略变严时，关闭其既有会话。
- 节点达到带宽上限或被隐藏时，停止新连接并关闭全部用户会话。
- 撤销生效 SLA：数据库状态提交后不超过一个刷新周期加 5 秒，即默认 65 秒。

## 3. 数据库故障

授权和计费故障分开处理：

### 3.1 授权读取失败

- 保留最后有效快照并进入 `DEGRADED_AUTH`。
- 按 1、2、4、8……60 秒指数退避重试，并加入抖动。
- 快照年龄超过 3600 秒后停止接受新会话，逐步 drain 存量会话。
- 重连成功后必须完整读取和编译，不用增量查询猜测遗漏变化。

### 3.2 流量写入失败

- 只要 outbox 可安全落盘，可以继续服务，不消耗授权快照的 3600 秒容忍度。
- 数据库恢复后按创建顺序重放。
- 任一批次失败不会阻塞更早批次的重试顺序，也不能跳过失败批次直接删除。
- outbox 达到 80% 容量时告警；达到硬上限时停止接收新会话。

### 3.3 本地持久化失败

无法创建、写入、`fsync` 或原子 rename 流量批次时，立即停止接收新会话。不能在无法保证计费的状态下继续产生新流量。

## 4. Outbox 文件合同

每个批次是独立、不可变、带版本的文件：

```text
state/outbox/<created_unix_nano>-<batch_uuid>.json
```

最低字段：

- schema version；
- batch UUID；
- node ID；
- 快照/配置版本；
- 创建时间；
- 冻结的 traffic rate；
- 按 user ID 排序的 raw uplink/downlink；
- payload SHA-256。

写入流程：临时文件写全、`fsync(file)`、rename、`fsync(directory)`。解析时拒绝未知版本、重复用户、负数、溢出、错误 node ID、hash 不一致和多余字段。

成功提交数据库后，先写完成标志或安全删除批次并 `fsync(directory)`。如果数据库已提交但删除前崩溃，重放由数据库 `batch_id` 保证不重复计费。

## 5. 流量统计边界

- 在用户认证成功并建立代理会话后开始统计。
- 认证握手、REALITY fallback/伪装流量不得计入任何用户。
- 用户上行是客户端到目标方向，下行是目标到客户端方向。
- TCP 重传不应重复计入应用代理字节。
- XUDP 按被代理的 UDP payload 统计，不包含 VLESS、XUDP、TCP、TLS 或 IP 头开销。
- Mux 下必须归属到实际用户，禁止落入共享 inbound 总计。
- 计数器使用无符号 64 位并检测溢出；转换数据库有符号 bigint 前检查范围。

## 6. 会话与限制

- 限制检查顺序：全局握手 -> 用户认证 -> 来源封禁 -> 用户连接/设备限制 -> 目标策略 -> 建立出站。
- 失败连接必须在所有计数器和会话表中对称释放。
- Mux/XUDP 子会话不能绕过每用户限制。
- 活跃 IP 在认证成功时登记，在最后会话结束后仍可保留到当前 60 秒报告周期结束。
- 域名目标必须对解析后的所有候选 IP 逐个检查；禁止 IP 不得通过 Happy Eyeballs 或重试旁路。
- DNS rebinding 场景每次新建出站均重新检查结果，不缓存未绑定策略的旧解析。

## 7. 优雅停止

收到 SIGTERM/SIGINT：

1. 原子切换到 `DRAINING`。
2. 关闭监听器，拒绝新会话。
3. 取消被撤销或超限会话，其余会话等待自然结束。
4. 在 120 秒上限到达时取消剩余会话。
5. 交换最后流量计数并安全写入 outbox。
6. 尝试最终数据库重放，但数据库不可用不阻止在 outbox 安全后退出。
7. 刷新日志并释放进程锁。

强制崩溃恢复测试必须证明最终流量批次不会丢失或重复。

## 8. 可观测性与告警

结构化日志必须包含 timestamp、level、component、node_id、event、错误类别；不得依赖自由文本解析计费。

最低告警：

- 授权快照年龄超过 5 分钟、30 分钟、接近 3600 秒；
- outbox 非空超过两个报告周期；
- outbox 使用超过 80%；
- 数据库连续失败；
- 配置/用户策略编译失败；
- 会话或握手限制持续触发；
- RSS、goroutine、FD 单调增长；
- REALITY fallback 流量异常增长；
- 节点心跳中断。
