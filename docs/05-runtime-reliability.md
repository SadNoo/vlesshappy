# 05. 运行时与可靠性

## 首次启动

启动必须依次完成：严格配置、secret 权限、状态目录单实例锁、数据库连接、`sort=15` 节点解析、完整用户快照、REALITY 公私钥配对和 Xray 入站构建。任一步失败都不得监听。

状态目录只保存锁文件，不保存流量、密码或私钥。

## 授权刷新

- 默认每 60 秒读取完整授权输入；
- 新快照完整验证后才发布；
- 用户禁用、到期、超额、UUID 或策略变化时定向撤销会话；
- 节点隐藏、类型变化、带宽耗尽或 REALITY 配置无效时停止服务；
- 数据库读取失败时暂用最后快照，超过 `auth_stale_seconds` 后 fail-closed。

## V2 模式流量上报

- 默认每 60 秒交换一次用户原始上下行计数；
- 使用一个 MySQL 事务更新用户、流量日志和节点带宽；
- 事务失败时将计数恢复到进程内 counter，下一周期重试；
- 普通计费写入失败只告警，不主动断开已有用户；
- 授权或倍率切换前先尝试按旧倍率结算，失败则不发布新快照。

已接受的边界：

- 数据库断开期间容器重启，尚未成功上报的进程内流量可能丢失；
- MySQL 已提交但客户端收到超时/EOF 时，恢复的计数可能再次提交；
- 因此不保证 exactly-once，目标是与现有 V2 后端一致；
- 正常数据库条件下不应产生持续误差，异常期误差必须在测试记录中量化。

## 数据库故障

授权读取和计费写入分别处理。短期计费失败不影响代理数据面；授权快照超过最大陈旧时间才停止。数据库恢复后，只重试当前进程仍持有的累计计数，不存在磁盘 outbox 恢复步骤。

## 会话和安全限制

握手、TCP、Mux 子流、XUDP、连接器、来源和目标策略仍由会话注册表强制执行。域名目标检查全部解析候选并固定到已检查 IP，避免 DNS rebinding 绕过。

## 停止

SIGTERM/SIGINT 时停止监听、关闭会话、交换最后计数并在 `shutdown_seconds` 内尝试一次最终数据库事务。数据库仍不可用时退出会丢失该未上报流量；这是 2.0 明确接受的 V2 兼容取舍。

## 最低告警

- 授权快照年龄接近上限；
- 数据库连续读取或写入失败；
- 流量报告恢复到进程内计数；
- 节点配置或用户策略编译失败；
- 会话/握手限制持续触发；
- RSS、goroutine 和 FD 持续增长；
- 节点心跳中断。
